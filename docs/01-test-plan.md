# CRM/ERP 测试靶场测试计划

## 1. 项目背景

本项目以一个自建的 **CRM/ERP 测试靶场** 为被测对象，模拟企业 CRM 与 ERP 系统的质量保障工作。系统覆盖客户、线索、商机、合同、产品、供应商、采购、库存、销售、发票、多租户与角色权限等核心模块，业务链路长、数据关联强，适合作为功能测试、接口测试、UI 自动化与性能测试的实战项目。

项目目标不是“证明系统有 Bug”，而是完整走一遍测试流程：

1. 需求分析与测试范围拆分；
2. 测试计划、测试用例设计；
3. 接口测试与数据校验；
4. UI 自动化框架搭建与回归；
5. 性能压测与瓶颈分析；
6. 缺陷记录、测试报告与复盘。

## 3. 测试范围

### 3.1 范围内

- **CRM**：客户建档/搜索/编辑/归档、负责人分配、线索创建、线索转商机、商机阶段推进、合同创建。
- **ERP**：产品创建/编辑、供应商创建、采购订单创建/确认/收货、销售订单创建/确认/发货、库存增加/扣减/调整、发票开具与金额校验。
- **权限**：未登录拦截、错误密码、销售角色权限边界、SaaS 管理访问控制、多租户数据隔离。
- **接口**：登录、客户 CRUD、产品创建与校验、销售订单创建/确认/发货/开票、采购订单创建/确认/收货、库存查询/调整、权限与租户隔离。
- **非功能**：登录、客户查询、客户创建、销售订单创建的并发性能基线。

### 3.2 范围外

- 源码级单元测试；
- 支付、税务、多币种等复杂财务场景；
- 移动端 App；
- 安全渗透测试（仅做基础权限校验与已知限制记录）；
- 生产环境部署与运维。

## 4. 测试策略

| 测试类型 | 方法 | 工具 |
|---|---|---|
| 功能测试 | 等价类、边界值、场景法、状态迁移 | 手工 + 测试用例 |
| 接口测试 | REST 协议、参数校验、业务码、DB 校验 | Postman / Newman、Python requests + pytest |
| UI 自动化 | POM 分层、显式等待、失败截图、Allure 报告 | Python + Selenium + Pytest + Allure |
| 性能测试 | 基准场景、并发梯度、TPS/P95/错误率 | Apache JMeter |
| 数据校验 | SQL 查询、接口返回与页面数据比对 | SQLite / Python |
| 权限测试 | 角色菜单、接口 403、租户数据 404 | pytest + Selenium |
| 缺陷管理 | 缺陷生命周期、严重级别、复现步骤 | Markdown 缺陷单 |

### 4.1 用例设计方法

- **等价类**：客户名称、电话、邮箱、订单数量、价格等字段的有效/无效等价类；
- **边界值**：数量 0/1/最大库存、金额 0/负数/小数位、名称长度；
- **场景法**：采购到入库、销售到出库、线索到商机到合同；
- **状态迁移**：报价单 → 销售订单 → 发货 → 发票；询价单 → 采购订单 → 收货；
- **错误推测**：重复提交、并发扣减、权限越权、必填字段缺失、重复收货/开票。

**准入：**
- 系统可访问，测试数据库初始化完成；
- 测试账号、角色、基础数据准备完成；
- 测试用例评审通过。

**准出：**
- P0/P1 用例全部执行，通过率 ≥ 95%；
- 阻塞性缺陷为 0；
- 接口、UI 自动化、性能报告产出；
- 测试总结与缺陷清单归档。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| SQLite 并发写锁 | 并发测试出现锁等待 | 开启 WAL + busy_timeout，控制并发梯度 |
| Flask 开发服务器性能有限 | TPS 偏低 | 说明是本地单机基线，不代表生产容量 |
| 测试数据污染演示数据 | 结果不可复现 | 使用独立测试库，数据加 `QA-`/`PERF-` 前缀，必要时 `python -m app.seed` 重置 |
| 浏览器驱动版本变化 | UI 脚本不稳定 | 使用 Selenium Manager 自动匹配驱动 + 显式等待 |
| 权限模型复杂 | 用例覆盖不足 | 先覆盖核心角色，再补充数据权限与租户隔离 |

## 10. 测试数据规范

- 客户名称统一前缀：`QA-CUST-<时间戳>` / `QA-API-CUST-<唯一串>`；
- 产品名称统一前缀：`QA-PROD-<时间戳>` / `QA-UI-产品-<唯一串>`；
- 压测客户统一前缀：`PERF-<UUID>`；
- 测试结束后通过接口归档/删除测试数据，避免污染演示数据；
- 需要恢复干净环境时执行 `python -m app.seed`。

## 11. 缺陷分级

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 / 严重 | 核心流程不可用、数据丢失、安全漏洞 | 无法登录、订单金额错误、跨租户数据泄露 |
| P1 / 高 | 主要功能异常、无绕过方案 | 并发超卖、重复收货导致库存翻倍 |
| P2 / 中 | 次要功能异常、有绕过方案 | 权限边界不严、字段校验缺失 |
| P3 / 低 | 文案、样式、体验问题 | 提示语不准确、按钮位置 |
